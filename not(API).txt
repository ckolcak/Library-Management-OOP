----------
API NEDIR?
----------
API bir yazılımın başka bir yazılım tarafından nasıl kullanılabiliceğini tanımlayan bir arayüz/kurallar bütünüdür.

--------------
WEB API NEDIR?
--------------
Web API arayuz fikrinin internet uzerinden çalışan halidir. Programım ile diğer program aynı bellek ustunde bulunmadıgı için aralarında
dogrudan iletişim kurulamaz. Bu iletişim HTTP Protokolu uzerinden gercekleşir. Sonuç olarak Web API bir URL'ye HTTP isteği gönderip
karşılığında bir cevap almaktır. 

---------------------
HTTP PROTOKOLU NEDIR?
---------------------
HTTP iki bilgisayarın internet üstünden birbirine veri isteyip vermesi için uydurulan bir kurallar butunudur.
Web siteleri aslında sunucu denen ve surekli calısan bilgisayarlar ustunde durur. Bu sunucu evimdeki bilgisayara cok benzer tek farkı
sürekli internete bağlı ve üzerinde gelicek istekleri bekleyen bir program(server yazılımı) var. Her bilgisayarın internete bağlanması
için bir IP adresi vardır, IP adresi aynı ev numarası gibidir. Insanlar daha rahat anlasın diye IP adresleri Domain isimlerine bağlıdır.

------------------
HTTP ISTEGI NEDIR?
------------------
HTTP isteği benim bir sunucuya gonderdiğim belirli bir yapıya sahip mesajdır. Şu parçalardan oluşur:
1.METHOD (ne yapmak istediğimi belirtir)
* GET - "bana veri ver"
* POST - "sana veri gonderiyorum bunu kaydet"

2.URL (nereye hangi kaynağa istek attığını belirtir)
*https://openlibrary.org/isbn/9780140328721.json

3.HEADERLAR (istekle alaklı ek bilgiler(ben kimim, mesajları hangi formatta istiyorum))

HTTP isteği karşısında sunucu bana bir cevap dondurur, bunun da yapısı var:
1.STATUS CODE (işlemin nasıl sonuçlandıgını üç haneli bir programda belirtir)
* 200 - başarılı
* 404 - aradığın şey bulunamadı
* 500 - sunucu tarafında bir hata oldu

2.BODY (asıl veri burda gelir,JSON formatında gelir)


-------------------
JSON FORMATI NEDIR?
-------------------
JSON (JavaScript Object Notation), verinin yazı olarak nasıl temsil edildiğini tanımlayan bir format. 
Web API'ler genelde cevaplarını JSON formatında döndürür, çünkü hem insan tarafından okunabilir hem de neredeyse 
her programlama dili tarafından kolayca işlenebilir.

-------------
SUNUCU NEDIR?
-------------
Sunucu başka bilgisayarlardan gelen istekleri bekleyen ve onlara cevap veren bir bilgisayar/programdır.
Sunucu sürekli açıktır, üzerinde istekleri almak için bir program çalışır, ve bir veri tabanına bağlıdır.
Veri tabanında kendi bilgilerini tutar program.

------------------
VERI TABANI NEDIR?
------------------
Veritabanı verinin düzenli, sorgulanabilir ve güvenli şekilde saklanması için tasarlanmış bir sistemdir.
Aynı benim file i/o yapım gibi.

--------------------------
libcurl KUTUPHANESI NEDIR?
--------------------------
libcurl internet üstünden veri alışverişi yapmamı sağlayan bir kutuphane. HTTP isteği gonder, cevap al gibi eylemleri bu kutuphane yapar.
Standart kutuphaneye dahil değildir. Şunları yapar: 
* URL'yi veririrz
* "Bu isteği gonder" komutunu veririz.
* Cevabı bize JSON metnini, ham string olarak iade eder.

--------------------------------
nlohmann/json KUTUPHANESI NEDIR?
--------------------------------
libcurl kutuphanesi bana ham bir JSON stringi getirir.
Örnek : {"title":"Matilda","number_of_pages":240,"authors":[{"key":"/authors/OL34184A"}]}

nlohmann/json un yaptıgı sey: Ham stringi alıp, benim c++ kodumda direkt erişebiliceğim bir nesneye çevirir.
Örnek: auto data = nlohmann::json::parse(jsonString);
       std::string title = data["title"];          // "Matilda"
       int pages = data["number_of_pages"];         // 240


-------------------
libcurl KUTUPHANESI
-------------------
Senin C++ programın
       ↓
     libcurl
       ↓
   HTTP Request
       ↓
      API
       ↓
   HTTP Response
       ↓
     libcurl
       ↓
Senin C++ programın

curl_easy_init() → curl'ü kullanmaya hazırlan
curl_easy_setopt() → "şu ayarları kullan" diye curl'e talimat ver
curl_easy_perform() → isteği gerçekten gönder
curl_easy_cleanup() → işin bitince temizle

curl_global_init()
        ↓
   "Curl'ü hazırla"
        ↓
curl_easy_init()
        ↓
   "Bir curl işlemi oluştur"
        ↓
curl_easy_perform()
        ↓
   "Request'i gönder"
        ↓
curl_easy_cleanup()
        ↓
   "Bu işlemi temizle"
        ↓
curl_global_cleanup()
        ↓
   "Curl'ü tamamen kapat"

----------------------------------------------
WRITECALLBACK FONKSIYONU (libcurl KUTUPHANESI)
----------------------------------------------
Fonksiyonun amacı: API'den / sunucudan gelen cevabı senin C++ programına aktarmak.

size_t WriteCallback(void* contents, size_t size, size_t nmemb, std::string* userp) {
    size_t totalSize = size * nmemb;
    userp->append((char*)contents, totalSize); yada (*userp).append((char*)contents, totalSize);
    return totalSize; 
}

contents → gelen verinin bulunduğu yer
size     → her parçanın boyutu
nmemb    → kaç parça geldiği
userp    → senin callback'e verdiğin ekstra veri

curl_easy_cleanup ile curl_global_cleanup fonksiyonları aralarındaki temel farklar şunlardır:
Kapsam (Scope):
curl_easy_cleanup(curl) tek bir oturumu/isteği (handle) temizler.
O an işi biten spesifik bir CURL* nesnesinin belleğini ve kaynaklarını serbest bırakır.
curl_global_cleanup() ise tüm libcurl kütüphanesini kapatır. 
Program genelinde kullanılan global kaynakları (örneğin ağ kütüphanelerinin başlatılması, SSL/TLS kütüphane state'leri vb.) tamamen sıfırlar.

Kullanım Zamanı:
curl_easy_cleanup, her bir HTTP/HTTPS isteği bittikten hemen sonra (veya program akışında o handle ile iş kalmadığında) çağrılır.
curl_global_cleanup, genellikle programın en son aşamasında (main fonksiyonunun çıkışına yakın bir yerde, uygulama kapanırken) bir kez çağrılır. 
Karşılığı olan curl_global_init() de programın başında bir kez çağrılmalıdır.

---------------------------
libcurl KUTUPHANESI MANTIGI
---------------------------
CURL* aslında yaptığımız HTTP işlemini temsil eden bir handle gibi düşünülebilir. 
curl_easy_init() ile yeni bir CURL işlemi oluşturup bunu bir CURL* değişkenine atarız ve 
oluşturduğumuz bu nesne bize bir HTTP/HTTPS işlemini temsil eder. 
Daha sonra curl_easy_setopt(curl, ...) ile bu işlemin ayarlarını yaparız; 
curl_easy_perform(curl) ile de o işlemi gerçekleştiririz. 
İşimiz bitince curl_easy_cleanup(curl) ile o işlemi temizleriz. 
Birden fazla HTTP/HTTPS işlemi yapmak istersek curl1, curl2 gibi farklı CURL* değişkenleri 
oluşturabiliriz ve her biri kendi ayarlarına sahip bağımsız bir işlem olur.
